# TracePad

Картинка-подложка поверх любых окон — для срисовки, трассировки, референсов и всего, что удобнее держать «на стекле» монитора, а не в отдельном окне.

Открыл референс, накинул его поверх Photoshop/браузера/IDE, подкрутил прозрачность, при желании сделал клик-сквозным — и рисуешь, глядя на образец, вместо Alt+Tab каждые пять секунд.

```
python tracepad.py путь/к/картинке.png
```

Зависимости: Python 3.10+, PySide6, Pillow.

Платформы: Windows — всё работает из коробки (WinAPI: клик-сквозь через `WS_EX_TRANSPARENT`, рабочая область с учётом DPI); Linux/X11 — всё (`XShape`, `_NET_WORKAREA`, `XGrabKey`); macOS — оверлей, зум и прозрачность есть, клик-сквозь и глобальные хоткеи — заглушки (в панели честное предупреждение).

---

## Что она умеет

Всё управление дублируется тремя способами: панель настроек, глобальные хоткеи, контекстное меню по правой кнопке на подложке.

| Что | Как |
| --- | --- |
| Переместить подложку | Потянуть мышью за саму картинку |
| Переместить панель | Потянуть за шапку (там, где TRACEPAD и имя файла) |
| Масштаб | Колесо мыши над подложкой (зум к курсору, ×1.12 за щелчок) |
| Прозрачность | Слайдер на панели, или Ctrl+Alt+T — мгновенно «затемняет» до 0.15 и возвращает обратно |
| Сетка | Ctrl+Alt+G, размер ячейки настраивается |
| Ч/б | Ctrl+Alt+B — убрать цвет, оставить тональность |
| Найти края | Ctrl+Alt+E — контурная обводка, сила регулируется |
| Зеркала | Ctrl+Alt+F / Ctrl+Alt+V — по горизонтали и вертикали |
| Клик-сквозь | Ctrl+Alt+C — мышь проходит НАСКВОЗЬ через подложку |
| Сброс вида | Двойной клик по подложке, или Ctrl+Alt+R |
| Панель | Ctrl+Alt+H — спрятать/показать |
| Новая картинка | Ctrl+Alt+O — диалог выбора файла |
| Выход | Ctrl+Alt+Q |

Позиция, размер и все настройки сохраняются сами (с дебаунсом 400 мс, не на каждое движение мыши) и восстанавливаются при следующем запуске. Файл настроек:

- Windows: `%APPDATA%\TracePad\state.json`
- Linux: `~/.config/tracepad/state.json`
- macOS: `~/Library/Application Support/TracePad/state.json`

Дальше — если ты не просто хочешь запустить, а хочешь понять, как это устроено.

## Сборка в один .exe

Коротко: **PyInstaller**. Nuitka тоже соберёт (код к нему готов), но для этого проекта PyInstaller выгоднее: собирается за ~50 секунд против ~10 минут у Nuitka с C-компиляцией всего Qt-биндинга, итоговый файл сопоставим по размеру (90+ МБ в обоих случаях — это цена PySide6), и не нужен компилятор C на машине. Nuitka берут, когда нужен антидекомпайл или чуть быстрее старт; для «картинка поверх окон» это из пушки по воробьям.

### Windows

```powershell
pip install pyinstaller PySide6 Pillow

pyinstaller --noconsole --onefile --name TracePad tracepad.py
```

Готово: `dist\TracePad.exe` — один файл, ~90 МБ, работает на чистой машине без Python.

Что значат флаги:

- `--onefile` — всё (интерпретатор, PySide6, Pillow, код) упаковывается в один exe. При запуске распаковывается во временный каталог `%TEMP%\_MEIxxxxx`. Минус: старт занимает пару секунд. Если хочется мгновенного запуска — убери флаг, получишь `dist\TracePad\` с `TracePad.exe` и кучей .dll внутри (распространять как папку/архив).
- `--noconsole` — без чёрного окна консоли позади GUI. Для отладки убери: увидишь stderr, в том числе трейсбеки из Qt-колбэков.
- `--name TracePad` — имя exe. Без него файл назывался бы `tracepad.exe` по имени скрипта.

Сборка проверена на реальном коде: `tracepad_qt` целиком попадает в бандл — собранный exe запускали с импорт-пробой всех модулей из распакованного архива. Код написан PyInstaller-friendly с самого начала: пакет импортируется как обычный `tracepad_qt.*`, `sys.path` правится только при обычном запуске из исходников, внешних ресурсов и Qt-плагинов нет — подводных камней типа «забыл data-файл» здесь не существует.

### Если всё-таки Nuitka

```powershell
pip install nuitka

python -m nuitka --onefile --windows-console-mode=disable ^
    --include-package=tracepad_qt ^
    --plugin-enable=pyside6 ^
    -o TracePad tracepad.py
```

Собирать желательно с `--include-package=tracepad_qt`: у Nuitka статический анализ иногда спотыкается об относительные импорты `from . import x` — явное указание пакета снимает вопрос. Плюс нужен MSVC или MinGW (Nuitka предложит автоматически скачать).

### macOS / Linux

Та же команда с PyInstaller, только флаг для консоли разный:

```bash
pip install pyinstaller PySide6 Pillow

pyinstaller --onefile --name TracePad tracepad.py              # Linux
pyinstaller --windowed --onefile --name TracePad tracepad.py   # macOS (.app)
```

На Linux глобальные хоткеи и клик-сквозь идут через X11 (python-xlib), Wayland-сессии полноценно не поддерживаются — окна появятся, но сквозные клики и хоткеи это X11 API.

## Как устроен код

~2100 строк на чистом PySide6, разбитых по одному вопросу на файл:

```
tracepad.py            точка входа: правит sys.path, зовёт tracepad_qt.app.main()
tracepad_qt/
  app.py               оркестратор: окна, хоткеи, подписки state, контекстное меню
  state.py             единственный источник правды + persistence (JSON)
  overlay.py           окно-подложка: drag, зум к курсору, колесо, dblclick
  panel.py             панель настроек: шапка-drag, свёртка, строки-переключатели
  controls.py          свои виджеты: Switch, слайдер, сегмент-контрол (все кастомные)
  renderer.py          PIL-конвейер: кэш фильтров, ч/б, края, сетка, зеркала, зум
  geometry.py          чистая математика: вписывание, кламп, зум-пределы (0.02–12)
  hotkeys.py           глобальные хоткеи: RegisterHotKey (Win) / XGrabKey (X11)
  winutil.py           платформенная магия: topmost, клик-сквозь, рабочая область
  style.py             QSS-тема, длительности анимаций (140 мс переходы)
```

Пара решений, которые объясняют, почему код выглядит именно так.

**State с подписками вместо разбросанных переменных.** Все настройки живут в одном объекте `State`. Виджеты подписываются на ключи (`state.subscribe("opacity", fn)`), реакции приложения — тоже. Меняешь значение в одном месте — панель и оверлей синхронизируются сами. Сравни с «естественным» подходом (IntVar + чекбокс + trace_add + ручная синхронизация), где любая связь — потенциальный цикл обновлений. Второй слой защиты: колбэк получает флаг `explicit` — изменил пользователь или программа, чтобы реакция на программное изменение не эхом возвращалась пользователю.

**Хоткеи в отдельном потоке, но GUI из него не трогается.** И RegisterHotKey/GetMessage (Windows), и XGrabKey (X11) — блокирующие API, им нужен свой поток. Но у Qt жёсткое правило: виджеты — только из главного потока. Поэтому поток хоткеев складывает действия в `collections.deque`, а GUI опрашивает её таймером каждые 80 мс. Дёшево, без блокировок, без сигналов через границу потоков.

**Клик-сквозь — через shape-регион окна, не через прозрачность.** Наивная реализация (полупрозрачное окно) теряет картинку. Правильная на Windows — `SetWindowRgn` с регионом-«ноликом», когда сквозной режим включён, и полный прямоугольник, когда выключен; на X11 — `XShape` с `ShapeInput`. Платформенная логика спрятана в `winutil.py`, остальной код о ней не знает.

**Рендер PIL-ем, не QPainter-ом.** Фильтры (ч/б, края, сетка) — попиксельные операции, для них естественнее Pillow: `ImageOps.grayscale`, `ImageFilter.FIND_EDGES`, линии сетки поверх буфера. Qt получает уже готовый QImage без глубокой копии. Промежуточный результат (фильтр до зума) кэшируется — переключение зума не пересчитывает ч/б заново. Двухступенчатый рендер: при интерактивном драге — быстрый черновик, после 160 мс покоя — финальное качество.

**Свои контролы вместо QCheckBox.** Дизайн-система в `controls.py` и `style.py`: пилюля-переключатель с анимацией 140 мс, безрамочный слайдер с сегмент-контролем, всё в едином QSS. Штатные виджеты пришлось бы стилизовать дольше, чем написать свои ~350 строк.

### Почему 2.1 и что чинилось в 2.1.1

Версия 2.0 была на tkinter — и после аудита переписана на Qt: у tk нет ни frameless-окон с приличным антиалиасингом, ни надёжного topmost, ни анимаций без ручного цикла. 2.1.1 — багфиксы, найденные первым живым запуском на Windows, где offscreen-тесты их не видели:

- свитчи падали с `RuntimeError: libshiboken` при быстрых кликах — анимации запускались с `DeleteWhenStopped`, C++-объект умирал, а Python-ссылка оставалась висячей. Убрано во всех 4 местах; ссылка держится до сигнала `finished`;
- панель не перетаскивалась: eventFilter сравнивал типы событий с магическими числами 27/28/29, которые в реальном enum'е Qt соответствуют совсем другим событиям (press=2, release=3, move=5). Заменено на `QEvent.MouseButtonPress` и компанию;
- подложка не реагировала на мышь: картинка жила в QLabel, который по умолчанию съедал все события мыши и не пропускал их окну. Лечится одной строкой — `WA_TransparentForMouseEvents`;
- плюс три некорректных конструктора `QTimer(parent, interval=…)` заменены на честный API `setInterval`/`setSingleShot` — включая дебаунс сохранения позиции, который из-за этого молча не работал.

Каждый фикс закрыт регрессионным тестом на синтетических событиях мыши через `QApplication.notify()` — ровно тех, что шлёт ОС (клик в свитч, быстрые тогглы, drag шапки, drag подложки, dblclick-сброс).

## Тесты

Два сьюта, оба запускаются без дисплея (`QT_QPA_PLATFORM=offscreen`):

```bash
QT_QPA_PLATFORM=offscreen python test_tracepad_qt.py     # 48/48: юнит + GUI-геометрия
QT_QPA_PLATFORM=offscreen python test_interactivity.py   # 12/12: события мыши через QApplication.notify
```

Первый проверяет математику и компоновку: вписывание, кламп, кэш рендера, persistence, рестарт-восстановление, DPI-консистентность, нулевые пересечения виджетов панели, свёртку 805↔60↔805, хоткеи-действия. Второй — реальную доставку событий: синтетический QMouseEvent по свитчу переключает состояние, быстрые двойные клики не роняют libshiboken, drag за шапку двигает панель ровно на дельту мыши и сохраняет позицию, dblclick по подложке зовёт сброс вида. Это тот класс багов, который offscreen-геометрия не ловит в принципе — события должен кто-то слать.

## Разработка

```bash
git clone <твой-репозиторий>
cd tracepad
python -m venv .venv
.venv\Scripts\activate             # Windows; Linux: source .venv/bin/activate
pip install -r requirements.txt
python tracepad.py любая-картинка.png
```

Код-стайл коротко: модули по одному вопросу, комментарии у неочевидных решений (а не пересказ кода), платформенные различия — только внутри `winutil.py` и `hotkeys.py`, остальной код платформо-независим. Добавить новую настройку — три шага: ключ в `DEFAULTS` (`state.py`), реакция в подписки (`app.py`), контрол на панель (`panel.py`); persistence и хоткеи подхватятся автоматически.
