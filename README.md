# TracePad

Картинка-подложка поверх любых окон — для срисовки, трассировки, референсов и всего, что удобнее держать «на стекле» монитора, а не в отдельном окне.

Открыл референс, накинул его поверх Photoshop/браузера/IDE, подкрутил прозрачность, при желании сделал клик-сквозным — и рисуешь, глядя на образец, вместо Alt+Tab каждые пять секунд. А с версии 2.2 — ещё и **Auto Drawing**: приложение само обводит найденные контуры мышью в графическом редакторе под референсом.

```
python tracepad.py путь/к/картинке.png
```

Зависимости: Python 3.10+, PySide6, Pillow, OpenCV (opencv-python), numpy; на Linux ещё python-xlib. Зависимости контуров/автрисовки (cv2/numpy/scipy) — см. requirements.txt.

Платформы: Windows — всё работает из коробки (WinAPI: клик-сквозь через `WS_EX_TRANSPARENT`, рабочая область с учётом DPI, автрисовка через SendInput); Linux/X11 — всё (`XShape`, `_NET_WORKAREA`, `XGrabKey`, автрисовка через XTEST); macOS — оверлей, зум и прозрачность есть, клик-сквозь, глобальные хоткеи и автрисовка — заглушки (в панели честное предупреждение).

## Что она умеет

Всё управление дублируется тремя способами: панель настроек, глобальные хоткеи, контекстное меню по правой кнопке на подложке.

| Что | Как |
| --- | --- |
| Переместить подложку | Потянуть мышью за саму картинку |
| Переместить панель | Потянуть за шапку (там, где TRACEPAD и имя файла) |
| Масштаб | Колесо мыши над подложкой (зум к курсору, ×1.12 за щелчок) |
| Прозрачность | Слайдер на панели, или Ctrl+Alt+T — мгновенно «затемняет» до 0.15 и возвращает обратно |
| Сетка | Ctrl+Alt+G, размер ячейки настраивается |
| Ч/б | Ctrl+Alt+B — убрать цвет, оставить тональность |
| Найти края | Ctrl+Alt+E — многоканальный детектор контуров (см. ниже), чувствительность на панели |
| Зеркала | Ctrl+Alt+F / Ctrl+Alt+V — по горизонтали и вертикали |
| Клик-сквозь | Ctrl+Alt+C — мышь проходит НАСКВОЗЬ через подложку |
| **Авто-рисовка** | Кнопка Draw, Ctrl+Alt+D или Esc — стоп |
| Сброс вида | Двойной клик по подложке, или Ctrl+Alt+R |
| Панель | Ctrl+Alt+H — спрятать/показать |
| Новая картинка | Ctrl+Alt+O — диалог выбора файла |
| Выход | Ctrl+Alt+Q |

Позиция, размер и все настройки сохраняются сами (с дебаунсом 400 мс, не на каждое движение мыши) и восстанавливаются при следующем запуске. Файл настроек:

- Windows: `%APPDATA%\TracePad\state.json`
- Linux: `~/.config/tracepad/state.json`
- macOS: `~/Library/Application Support/TracePad/state.json`

Дальше — если ты не просто хочешь запустить, а хочешь понять, как это устроено.

## Auto Drawing: как этим пользоваться

Сценарий из жизни: ты рисуешь персонажа в Krita/Photoshop/Aseprite и хочешь аккуратный контур по референсу.

1. Открываешь референс в TracePad, включаешь контуры (Ctrl+Alt+E), подкручиваешь чувствительность: должны быть видны все нужные границы и не лезть шумовое мусор.
2. Ставишь окно TracePad поверх холста редактора, выравниваешь картинку по холсту.
3. В редакторе выбираешь чёрный цвет и кисть. Только кисть и цвет — больше ничего приложение само не настраивает.
4. Жмёшь Draw (или Ctrl+Alt+D). Панель спрячется, курсор пройдёт по всем контурам, обводя их.
5. Esc или ещё раз Draw — мгновенный стоп (перо поднимается).

Скорость регулируется сегментом «точно / обычно / быстро» — это компромисс между плотностью точек и временем обведения. Волшебная кнопка отмены — Esc: остановка проверяется между КАЖДЫМ ходом курсора.

Границы безопасности, вшитые в код: курсор никогда не выходит за прямоугольник картинки (план клиппится по bbox оверлея до старта); любое движение твоей реальной мыши во время рисования останавливает обведение (watchdog сравнивает позицию курсора с плановой после каждого события); ошибка любого системного вызова поднимает кнопку мыши и глушит поток; автрисовка не трогает настройки клик-сквозь и always-on-top оверлея.

Ограничение первой версии, о котором честно сказать: не рисуются заливки, цвета не меняются, кисть не выбирается. Только обводка. На macOS автрисовка не поддерживается (как и клик-сквозь): SendInput/XTEST на macOS нет.

## Сборка в один .exe

Коротко: **PyInstaller**. Nuitka тоже соберёт (код к нему готов), но для этого проекта PyInstaller выгоднее: собирается за ~50 секунд против ~10 минут у Nuitka с C-компиляцией всего Qt-биндинга, итоговый файл сопоставим по размеру (90+ МБ в обоих случаях — это цена PySide6), и не нужен компилятор C на машине. Nuitka берут, когда нужен антидекомпайл или чуть быстрее старт; для «картинка поверх окон» это из пушки по воробьям.

### Windows

```powershell
pip install pyinstaller PySide6 Pillow

pyinstaller --noconsole --onefile --name TracePad tracepad.py
```

Готово: `dist\TracePad.exe` — один файл, ~90 МБ, работает на чистой машине без Python.

Что значат флаги:

- `--onefile` — всё (интерпретатор, PySide6, Pillow, код) упаковывается в один exe. При запуске распаковывается во временный каталог `%TEMP%\_MEIxxxxx`. Минус: старт занимает пару секунд. Если хочется мгновенного запуска — убери флаг, получишь `dist\TracePad\` с `TracePad.exe` и кучей .dll внутри (распространять как папку/архив).
- `--noconsole` — без чёрного окна консоли позади GUI. Для отладки убери: увидишь stderr, в том числе трейсбеки из Qt-колбэков.
- `--name TracePad` — имя exe. Без него файл назывался бы `tracepad.exe` по имени скрипта.

Сборка проверена на реальном коде: `tracepad_qt` целиком попадает в бандл — собранный exe запускали с импорт-пробой всех модулей из распакованного архива. Код написан PyInstaller-friendly с самого начала: пакет импортируется как обычный `tracepad_qt.*`, `sys.path` правится только при обычном запуске из исходников, внешних ресурсов и Qt-плагинов нет — подводных камней типа «забыл data-файл» здесь не существует.

### Если всё-таки Nuitka

```powershell
pip install nuitka

python -m nuitka --onefile --windows-console-mode=disable ^
    --include-package=tracepad_qt ^
    --plugin-enable=pyside6 ^
    -o TracePad tracepad.py
```

Собирать желательно с `--include-package=tracepad_qt`: у Nuitka статический анализ иногда спотыкается об относительные импорты `from . import x` — явное указание пакета снимает вопрос. Плюс нужен MSVC или MinGW (Nuitka предложит автоматически скачать).

### macOS / Linux

Та же команда с PyInstaller, только флаг для консоли разный:

```bash
pip install pyinstaller PySide6 Pillow

pyinstaller --onefile --name TracePad tracepad.py              # Linux
pyinstaller --windowed --onefile --name TracePad tracepad.py   # macOS (.app)
```

На Linux глобальные хоткеи и клик-сквозь идут через X11 (python-xlib), Wayland-сессии полноценно не поддерживаются — окна появятся, но сквозные клики и хоткеи это X11 API.

## Как устроен код

~2100 строк на чистом PySide6, разбитых по одному вопросу на файл:

```
tracepad.py            точка входа: правит sys.path, зовёт tracepad_qt.app.main()
tracepad_qt/
  app.py               оркестратор: окна, хоткеи, подписки state, Draw-цикл
  state.py             единственный источник правды + persistence (JSON)
  overlay.py           окно-подложка: drag, зум к курсору, колесо, dblclick
  panel.py             панель настроек: шапка-drag, свёртка, строки-переключатели
  controls.py          свои виджеты: Switch, слайдер, сегмент-контрол (все кастомные)
  renderer.py          PIL-конвейер: кэш фильтров, ч/б, контуры, сетка, зеркала, зум
  edges.py             детектор контуров: Lab-градиенты, NMS, гистерезис (Auto Draw)
  strokes.py           карта контуров -> траектории: findContours, RDP, порядок обхода
  autodraw.py          исполнитель: SendInput (Win) / XTEST (X11), поток, watchdog
  geometry.py          чистая математика: вписывание, кламп, зум-пределы (0.02–12)
  hotkeys.py           глобальные хоткеи: RegisterHotKey (Win) / XGrabKey (X11)
  winutil.py           платформенная магия: topmost, клик-сквозь, рабочая область
  style.py             QSS-тема, длительности анимаций (140 мс переходы)
```

Пара решений, которые объясняют, почему код выглядит именно так.

**State с подписками вместо разбросанных переменных.** Все настройки живут в одном объекте `State`. Виджеты подписываются на ключи (`state.subscribe("opacity", fn)`), реакции приложения — тоже. Меняешь значение в одном месте — панель и оверлей синхронизируются сами. Сравни с «естественным» подходом (IntVar + чекбокс + trace_add + ручная синхронизация), где любая связь — потенциальный цикл обновлений. Второй слой защиты: колбэк получает флаг `explicit` — изменил пользователь или программа, чтобы реакция на программное изменение не эхом возвращалась пользователю.

**Хоткеи в отдельном потоке, но GUI из него не трогается.** И RegisterHotKey/GetMessage (Windows), и XGrabKey (X11) — блокирующие API, им нужен свой поток. Но у Qt жёсткое правило: виджеты — только из главного потока. Поэтому поток хоткеев складывает действия в `collections.deque`, а GUI опрашивает её таймером каждые 80 мс. Дёшево, без блокировок, без сигналов через границу потоков.

**Клик-сквозь — через shape-регион окна, не через прозрачность.** Наивная реализация (полупрозрачное окно) теряет картинку. Правильная на Windows — `SetWindowRgn` с регионом-«ноликом», когда сквозной режим включён, и полный прямоугольник, когда выключен; на X11 — `XShape` с `ShapeInput`. Платформенная логика спрятана в `winutil.py`, остальной код о ней не знает.

**Контуры — не FIND_EDGES.** Старый режим контуров был визуальным эффектом (Laplacian + порог): на реальных картинках он давал F1 = 0.04 против ground truth — 98% найденного это шум. Новый детектор (`edges.py`) решает три проблемы сразу: (1) границы ищутся в Lab, а не в grayscale — цветовые границы при равной яркости (красное на сером) gray не видит в принципе, а Lab-каналы ловят; (2) каналы сливаются ДО non-max suppression — иначе три Canny по каналам дают тройные линии; (3) пороги не фиксированные и не перцентильные, а якорятся на статистику магнитуды (mean + 2std) — у каждой картинки свой контраст, и порог должен подстраиваться. Итог: F1 0.96-1.00 на тестовых сценах, включая тонкие 3px-детали. Большие кадры детектируются на даунскейле (4K → 306 мс вместо 1128, качество не меняется — контуры и так субпиксельные).

**Траектории — findContours, не скелетный граф.** Превращение пиксельной маски в полилинии — это классическая задача скелетизации, и первая реализация была именно такой (deg-классификация пикселей + обход цепочек). Она рассыпалась: NMS кодирует изгибы диагональными лестницами, в 8-связности почти каждая точка изгиба имеет 3-4 соседа, и трассировка режет линии на обрывки. Вместо хрупких эвристик взят `cv2.findContours`: OpenCV решает лестницы, связность и порядок точек за один проход C++-кода. Дальше — RDP-упрощение с жёстким допуском 0.75px (убирает субпиксельную лесенку, не срезая углы; никакого Безье-сглаживания — углы должны остаться углами) и greedy-порядок обхода по ближайшим концам штрихов (минимум холостых перелётов). Итог: покрытие маски траекториями 1.000, звезда из 8 линий обводится 3 штрихами.

**Auto Drawing: один рабочий поток, ноль новых таймеров.** Исполнитель автрисовки — тот же паттерн, что хоткеи: системные вызовы (SendInput/XTEST) блокирующие и не могут жить в GUI-потоке, поэтому отдельный поток + deque событий, который опрашивает УЖЕ существующий 80-мс таймер. Паника-стоп проверяется после каждого хода: курсор должен быть там, куда мы его только что поставили (SendInput на Windows и XTEST на X11 это гарантируют); уехал — значит пользователь вмешался, поднимаем перо. Маппинг координат учитывает всё окно сразу: зум, позицию, флипы — курсор обводит то, что видит пользователь, включая зеркальные отображения.

**Рендер PIL-ем, не QPainter-ом.** Фильтры (ч/б, контуры, сетка) — попиксельные операции, для них естественнее Pillow. Qt получает уже готовый QImage без глубокой копии. Промежуточный результат (фильтр до зума) кэшируется — переключение зума не пересчитывает ч/б заново. Двухступенчатый рендер: при интерактивном драге — быстрый черновик, после 160 мс покоя — финальное качество.

**Свои контролы вместо QCheckBox.** Дизайн-система в `controls.py` и `style.py`: пилюля-переключатель с анимацией 140 мс, безрамочный слайдер с сегмент-контролем, всё в едином QSS «ночное стекло». Штатные виджеты пришлось бы стилизовать дольше, чем написать свои ~350 строк.

### Почему 2.2 (история версий)

Версия 2.0 была на tkinter — и после аудита переписана на Qt: у tk нет ни frameless-окон с приличным антиалиасингом, ни надёжного topmost, ни анимаций без ручного цикла. 2.1.1 — багфиксы живого запуска на Windows (висячие QPropertyAnimation, магические числа eventFilter, QLabel, съедающий события; каждый закрыт регрессионным тестом). 2.2 — контуры и Auto Drawing: новый детектор (F1 0.04 → 0.96), траектории из findContours, автрисовка через SendInput/XTEST с watchdog и Esc-стопом, производительность 4K (детект 1.1 с → 306 мс через даунскейл без потери качества).

## Тесты

Три сьюта, все запускаются без дисплея (`QT_QPA_PLATFORM=offscreen`):

```bash
QT_QPA_PLATFORM=offscreen python test_tracepad_qt.py     # 48/48: юнит + GUI-геометрия
QT_QPA_PLATFORM=offscreen python test_interactivity.py   # 12/12: события мыши через QApplication.notify
QT_QPA_PLATFORM=offscreen python test_autodraw.py         # 20/20: контуры, траектории, автрисовка, E2E
```

Первый проверяет математику и компоновку: вписывание, кламп, кэш рендера, persistence, рестарт-восстановление, DPI-консистентность, нулевые пересечения виджетов панели, свёртку, хоткеи-действия. Второй — реальную доставку событий: синтетический QMouseEvent по свитчу переключает состояние, drag за шапку двигает панель ровно на дельту мыши, dblclick по подложке зовёт сброс вида. Третий — новую функциональность: F1 детектора на ground truth (со скриншотом сравнения до/после в заголовке edges.py), покрытие траекториями (должно быть 1.000), RDP не срезает углы (отклонение <= допуска), маппинг флипов/зума в экранные координаты, и E2E: draw_start в живом GUI прячет панель, обводит, возвращает панель, пишет статус. На Linux с X-сервером третий сьют прогоняет автрисовку живьём (XTEST двигает реальный курсор).

## Разработка

```bash
git clone <твой-репозиторий>
cd tracepad
python -m venv .venv
.venv\Scripts\activate             # Windows; Linux: source .venv/bin/activate
pip install -r requirements.txt
python tracepad.py любая-картинка.png
```

Код-стайл коротко: модули по одному вопросу, комментарии у неочевидных решений (а не пересказ кода), платформенные различия — только внутри `winutil.py` и `hotkeys.py`, остальной код платформо-независим. Добавить новую настройку — три шага: ключ в `DEFAULTS` (`state.py`), реакция в подписки (`app.py`), контрол на панель (`panel.py`); persistence и хоткеи подхватятся автоматически.
